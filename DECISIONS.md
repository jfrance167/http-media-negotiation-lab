# Decisions

- Build a standard-library normalized model rather than adopt a raw parser. Reviewed Werkzeug and WebOb have broader recovery, parameter and tie policies; those differences are fit observations, not validated vulnerabilities. Research links, pinned source identities and access limits remain in RESEARCH.md and research/source-index.json.
- Represent quality as exact integer thousandths. Resolve the most-specific matching range for each candidate before comparing quality across candidates. Preserve all equal-best offers; selection belongs to a separate assumed server policy.
- Keep absent, present-empty and unknown Accept distinct. Equal-specificity conflicting qualities are ambiguous rather than assigned an invented winner. Unsupported context and unknown server policy remain explicit.
- Limit parameters to declared text/plain format=fixed/flowed. Apply case-insensitive matching only within that documented subset. Do not invent charset semantics, body defaults, codecs or structured-suffix wildcards.
- Validate the whole document before semantic shortcuts. Exact built-in identity guards avoid user-defined hooks. Bound input, tree traversal and complete report serialization; use fresh-file delivery and fixed diagnostics.
- Freeze full independently specified expected reports before application code. A later failing test exposed a depth-definition mismatch: depth now explicitly counts containers. Preserve the original contract/receipt and correction chronology; input and expected fixture bytes did not change.
- Use the reviewed local Ollama helper for a bounded source-reminder extraction. Codex retained implementation/security judgments; the limited 2B worker was unsuitable for those decisions. Local output was adequate, so no remote route, paid call, model download or new service was used.
- Complete locally under approved stages 1–4. No Git mutation, publication, deployment, external messaging or successor project is part of this closeout.
